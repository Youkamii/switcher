# API 키 등록과 사용

일반 모드 상단의 **API 키 등록**에서 시작한다. 등록 화면과 실행 화면은 [전체 개선 이미지](design/complete-preview.png)에서 함께 볼 수 있다.

## 처음 등록할 때

1. 상단 **API 키 등록**을 누르고 **Claude** 또는 **OpenAI · Codex**를 선택한다.
2. 키가 없으면 **키 발급 페이지 열기 ↗**를 누른다. Claude는 사용할 워크스페이스를 지정해 키를 발급한다. 발급 시 설정한 만료일·권한도 확인한다. [Claude 공식 안내](https://platform.claude.com/docs/en/get-api-key), [OpenAI 키 관리](https://platform.openai.com/api-keys).
3. 연결 이름과 키를 입력하고 **저장하고 확인**을 누른다. 이름에는 영문·숫자·`-`·`_`를 쓴다. 대소문자는 구분하지 않는다.
4. 키 저장 뒤 모델 목록을 자동 조회한다. **연결 확인됨**은 조회 성공을 뜻하며, 생성 권한·잔액·요금 한도까지 검증한 것은 아니다. 확인이 실패해도 저장 상태와 실패 이유를 보여준다.
5. 같은 창의 **실행 명령 복사**를 누르고 작업할 프로젝트의 기존 터미널에 붙여넣는다. macOS는 bash/zsh, Windows는 PowerShell에서 사용한다. 명령에는 키 원문이 없다.
6. Claude CLI가 API 사용 확인을 물으면 내용을 확인한다. API 사용은 구독과 별도 과금되며, Claude는 키를 환경변수로 제공하면 최초 사용 시 확인을 요청할 수 있다. [공식 인증 문서](https://code.claude.com/docs/en/authentication).

연결 목록에서 터미널 아이콘을 누르면 같은 실행 명령을 다시 볼 수 있다. 작은 모드에서는 상단 보기 버튼을 눌러 **1 일반**으로 돌아오면 등록·관리를 할 수 있다. 새 터미널 창은 자동으로 만들지 않는다.

## 연결 목록의 아이콘

| 아이콘 | 동작 |
| --- | --- |
| 터미널 | 실행 명령 보기·복사 |
| 순환 화살표 | 모델 목록으로 다시 확인 |
| 열쇠 | 기존 연결의 키 교체 |
| 휴지통 | 삭제 준비. 3초 안에 한 번 더 눌러 삭제 |

새 등록에서 기존 이름을 입력하면 오류를 표시한다. 교체할 때는 **열쇠 아이콘**을 사용한다. 기존 키를 화면으로 되돌려 보내지 않으며, 새 키를 저장하면 이전 확인 결과를 초기화한다. 확인 중 키가 교체되거나 연결이 삭제되면 옛 요청 결과로 상태를 덮어쓰지 않는다.

확인 결과와 시각은 비밀이 아닌 메타데이터에 보관한다. 앱을 다시 열어도 마지막 확인 상태를 볼 수 있지만 실시간 접속 보장은 아니므로 필요하면 다시 확인한다. 삭제 확인은 포인터 이탈·다른 곳 클릭·포커스 상실과 경과 시간으로 해제하므로, 비활성 macOS 창의 타이머 지연에 의존하지 않는다.

## 기존 로그인과 키 저장

- macOS는 Keychain, Windows는 현재 사용자에게 묶인 DPAPI 암호문에 키를 보관한다. 입력값은 저장 성공·실패·취소 때 비운다. 목록·메타데이터·실행 스크립트에는 키 원문이 없다.
- 실행 명령은 연결별 `~/.switcher/api-workspaces/<provider>-<name>/`을 CLI 설정·기록 폴더로 쓴다. 기존 OAuth 인증 파일, 셸 설정, 전역 환경변수는 변경하지 않는다.
- 기존 `claude`/`codex` 명령은 기존 설정대로 실행한다. API를 쓰려는 세션은 복사한 명령으로 시작한다. 구독 오류나 사용량 초과를 이유로 자동으로 유료 API로 바꾸지 않는다.
- 키 교체는 다음 CLI 실행부터 적용된다. 이미 실행 중인 CLI에는 영향을 주지 않는다.
- 삭제는 로컬 키·메타데이터·실행 스크립트를 지운다. CLI 작업 기록은 남는다. 공급자 서버의 키 폐기는 키 발급 페이지에서 별도로 한다.

macOS 명령은 `/bin/bash '/…/.switcher/api-connections/claude/work/run.sh'`, Windows는 `powershell.exe -NoProfile -File '…\run.ps1'` 형태다. 끝에 CLI 인자를 추가할 수 있다. 해당 CLI가 터미널 PATH에 있어야 한다. Windows 실행 정책이 스크립트를 제한하면 조직 정책을 확인한다. 앱이 정책을 자동 해제하지 않는다.

## 인증 오류를 구분하는 기준

| 표시 | 처리 |
| --- | --- |
| 구독 액세스 토큰 갱신 필요 | 해당 계정 CLI를 실행한 뒤 사용량 새로고침 |
| CLI 사용 중 · 갱신 대기 | CLI가 보유한 토큰과 충돌하지 않도록 위젯 갱신을 보류한 상태. CLI 종료 후 자동 재시도하며 재로그인이 필요한 상태는 아님 |
| 저장된 갱신 토큰 거부 | 계정 카드의 순환 화살표 **다시 연결**에서 같은 계정 로그인 |
| 권한 거부 | 계정·프로젝트·조직의 접근 정책 확인 |
| API 키 거부 | 연결 목록의 열쇠 아이콘으로 키 교체 |
| API 조회 권한 부족 | 모델 목록 조회 권한 확인. 생성 권한과는 별개 |
| 요청 제한·네트워크 실패 | 잠시 후 연결 확인 재시도 |
| Codex 파일 외 인증 저장소 | 지원하지 않는 저장소의 덮어쓰기를 차단한 상태. API 연결은 계속 사용 가능 |

현재 구독 전환은 앱 프로세스의 `CODEX_HOME`을 따르며 파일 저장소만 지원한다. Codex `keyring`·`auto`·`ephemeral`을 감지하면 저장·전환을 막는다. 이 설정을 자동으로 바꾸지 않는다.

## 지원·검증 범위

공식 Anthropic/OpenAI 키를 지원한다. Claude는 워크스페이스에 연결된 키를 기준으로 한다. 별도 워크스페이스 헤더가 필요한 조직 범위 키, 사용자 지정 Base URL, Azure/Bedrock, 비용·쿼터 집계는 포함하지 않는다.

가짜 키를 쓴 실제 macOS 키체인 왕복·삭제, 생성 런처의 환경·인자 격리, 설치된 Claude/Codex의 `--version` 실행을 검증했다. 모델 목록의 정상·오류·리다이렉트 응답은 로컬 서버로 검사했다. 실제 유료 API 호출·구독 전환·Windows 실행은 검증하지 않았다. 전체 검사 결과는 [적용 현황](IMPLEMENTATION_STATUS.md)에 정리했다.
