# API 키 등록과 사용

버튼은 **계정·API 추가** 하나로 유지하며 **구독 로그인 / API 키 등록**을 고른다. v2.1.0의 첫 버튼 이름은 **계정 추가**이다. 이를 눌렀을 때 선택 화면 없이 곧바로 로그인으로 넘어가면 위젯 우클릭 → **업데이트 확인**으로 실행 중인 앱을 갱신한다. npm 설치본이 새 버전이어도 기존 프로세스는 계속 표시될 수 있다.

## Codex 계정 전환 범위

위젯은 현재 인증을 먼저 백업하고 선택한 계정의 `auth.json`을 적용한다. **이미 실행 중인 Codex의 인증까지 즉시 바꾸지는 않는다.** Codex CLI 0.167.0은 인증을 메모리에 유지하며 외부 파일 변경을 자동으로 읽지 않는다. 401 복구 시에도 다른 계정으로의 재읽기를 허용하지 않는다. [해당 버전 AuthManager 구현](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/login/src/auth/manager.rs).

기존 Codex를 종료한 뒤 같은 터미널에서 `codex resume`으로 이어가면 선택한 인증을 새로 읽는다. 별도 터미널 창이나 로그아웃·브라우저 로그인을 요구하는 흐름이 아니다. 화면은 **선택됨**과 다음 실행 적용 안내로 이를 구분한다. 실사용 세션을 종료하거나 입력을 주입해 강제로 바꾸는 기능은 구현하지 않았다.

`node scripts/check-codex-session-auth.mjs`는 격리된 홈·가짜 OAuth 계정 두 개로 설치된 Codex를 실행한다. 기존 프로세스는 A, 파일 교체 후 새 프로세스는 B를 읽는지 검사한다. 생성 요청이나 실계정 토큰을 사용하지 않는다. 이 검사는 로그인 인식 범위이며 실제 모델 호출 성공을 뜻하지 않는다.

## API 등록

일반 모드에서 해당 제공자의 **계정 추가 → API 키 → 저장하고 사용**으로 설정한다. 같은 추가 창의 **구독 로그인**에서 구독 계정을 추가한다. 별도 실행 명령을 복사할 필요가 없다. 다음에 평소처럼 `claude` 또는 `codex`를 실행하면 선택한 API를 사용한다.

## 등록·전환

1. **Claude** 또는 **Codex** 옆 **계정 추가**를 누르고 **API 키**를 선택한다. 별도 API 등록 버튼은 없다.
2. 키가 없으면 **키 발급 페이지 열기 ↗**를 누른다. Claude 키는 사용할 워크스페이스를 지정해 발급한다. [Claude 공식 안내](https://platform.claude.com/docs/en/get-api-key), [OpenAI 키 관리](https://platform.openai.com/api-keys).
3. 연결 이름·키·월 예산을 입력하고 **저장하고 사용**을 누른다. 기본 월 예산은 API별 **$195**다. 이름은 영문·숫자·`-`·`_`를 사용하며 대소문자를 구분하지 않는다.
4. **API 사용 중**이 표시되면 설정 적용이 끝난 것이다. 모델 목록 조회 결과는 별도로 표시한다. 조회 성공은 생성 권한·잔액까지 보장하지 않는다.
5. 구독으로 돌아갈 때는 원하는 구독 계정의 **전환**을 누른다. API 카드의 **해제**는 API 선택 직전 설정을 복원한다.

이미 등록한 연결은 카드의 **사용**만 누르면 된다. 키를 다시 입력하지 않는다. 네 가지 모드 모두 선택된 API를 표시하며, 등록·교체·삭제는 일반 모드에서 한다. API 사용은 구독과 별도 과금된다. 실행 중인 CLI의 인증 메모리는 바꾸지 않으므로 다음 CLI 실행부터 적용된다. 새 터미널 창은 만들지 않는다.

등록·키 교체·완료 화면이 열린 상태에서도 **창 상단이나 대화상자 제목을 잡아 이동**할 수 있다. 이동 중 입력값은 유지한다.

## 연결 목록

| 버튼 | 동작 |
| --- | --- |
| 사용 / 해제 | 저장된 API 적용 / 이전 설정 복원 |
| 순환 화살표 | 모델 목록으로 연결 확인 |
| 열쇠 | 새 키로 교체하고 적용 |
| 휴지통 | 3초 안에 한 번 더 눌러 삭제. 사용 중이면 설정 복원 후 삭제 |

같은 이름의 새 등록은 기존 키를 덮어쓰지 않는다. 교체에는 열쇠 버튼을 사용한다. 키 저장에는 성공했지만 설정 적용이 실패하면 **키 저장 완료**와 오류, **사용** 재시도 버튼을 표시한다. 저장한 키로 재시도하므로 재입력할 필요가 없다.

확인 결과·시각은 메타데이터에 보관하며, 키 교체 시 초기화한다. 확인 중 교체·삭제가 일어나면 낡은 응답을 반영하지 않는다. 입력값은 저장 성공·실패·취소 때 지우고 다시 표시하지 않는다.

## API별 사용량과 $195 예산

API 카드에 이번 달 사용 금액·예산·남은 금액·사용률을 표시한다. 기본 월 예산은 각 API 연결마다 **$195**이며, 등록할 때 또는 카드의 **사용량·예산 설정**(연필)에서 변경한다. 컴팩트·미니멀·엣지에서도 선택된 API의 금액과 막대를 표시한다.

- **직접 입력**: 공급자 비용 페이지에서 확인한 이번 달 USD 금액을 저장한다. 다른 API 연결의 금액·예산에는 영향을 주지 않는다.
- **자동 조회**: 별도의 **비용 조회용 관리자 API 키**와 조회할 **API key ID**를 등록한다. 조회용 키는 실행 키와 다른 OS 보안 저장소 항목으로 보관하며 화면으로 돌려주지 않는다. ID는 비밀 키(`sk-…`)가 아니라 공급자 키 목록의 식별자다. 관리자 권한이 없으면 직접 입력을 사용한다.
- **미조회·실패**: 모르는 금액을 `$0`으로 표시하지 않는다. `—`로 표시하고, 조회 실패 시 마지막으로 확인한 금액과 오류를 함께 남긴다. 전체 페이지를 성공적으로 읽은 때만 합계를 갱신한다.
- **월 기준**: UTC 달력의 월간 합계다. 월이 바뀌면 전월 금액을 당월 사용량으로 보여주지 않는다. 예산 설정은 유지한다.
- **초과 표시**: 예산의 80%부터 경고색, 100%부터 초과 금액을 표시한다. 막대는 100%에 멈춰도 실제 초과 금액은 그대로 보인다. 이 예산은 위젯의 표시 기준이며 공급자의 결제 상한을 변경하거나 실행 중인 CLI를 차단하지 않는다.

Claude 자동 조회는 Analytics Cost API에서 `api_key_ids[]`로 필터링하며, 소수 센트를 달러로 변환한다. 관리자 키 또는 적절한 Analytics 권한이 필요하고 집계가 지연될 수 있다. [Claude 비용 API](https://platform.claude.com/docs/en/api/beta/organization/analytics/cost/list). OpenAI는 관리자 비용 API를 같은 API 키 ID로 필터링한다. [OpenAI Costs API](https://developers.openai.com/api/reference/resources/admin/subresources/organization/subresources/usage/methods/costs), [관리자 키 안내](https://developers.openai.com/api/docs/guides/admin-apis).

자동 조회는 화면 갱신 시 최대 5분마다 요청하며 비용 새로고침 버튼으로 즉시 재조회할 수 있다. 공급자가 보고한 비용의 반영 시점과 최종 청구서에는 차이가 있을 수 있다. 직접 입력으로 바꾸거나 연결을 삭제하면 등록된 조회용 키도 제거한다.

## 적용 방식과 복원

- 저장된 키는 macOS Keychain / Windows 현재 사용자 DPAPI로 보호한다. 목록·로그·보조 스크립트에 키 원문을 넣지 않는다.
- Claude는 사용자 `settings.json`의 공식 `apiKeyHelper`가 보안 저장소에서 키를 읽는다. 구독 OAuth 자격증명은 보존한다. 충돌하는 사용자 설정의 API 인증·클라우드 환경 항목은 적용 전에 백업하고, 공식 Anthropic 엔드포인트를 선택한다. [Claude 인증 우선순위](https://code.claude.com/docs/en/authentication), [apiKeyHelper](https://code.claude.com/docs/en/settings-reference#apikeyhelper).
- Codex는 사용자 `config.toml`에 공식 OpenAI API 공급자를 선택하고 표준 `auth.json`에 활성 API 키를 쓴다. **Codex가 읽는 활성 인증 파일에는 키가 들어간다.** Unix에서는 0600 권한으로 쓰며, 저장 연결의 정본은 OS 보안 저장소에 둔다. 기존 인증은 전환 전에 백업한다. [Codex 인증 저장소](https://learn.chatgpt.com/docs/auth).
- 복원 기록은 `~/.switcher/api-active/<provider>/`에 저장한다. 앱이 적용한 값과 현재 값이 같은 항목만 되돌리고, 사용자가 그 사이 바꾼 다른 설정·새 OAuth 로그인은 보존한다. Codex TOML의 다른 설정과 주석도 유지한다.
- API를 명시적으로 선택하면 자동 계정 전환(TFSD)을 해제한다. 구독 오류·사용량 초과 때문에 API로 자동 전환하지 않는다.
- 삭제는 로컬 키·연결 정보·보조 스크립트를 지운다. 공급자 서버의 키 폐기는 발급 페이지에서 별도로 한다.

사용자·프로젝트·조직 정책의 우선순위는 CLI가 결정한다. 별도 구성 경로, 프로젝트 인증 덮어쓰기, 관리 정책으로 제한된 환경은 기본 사용자 설정 적용만으로 보장하지 않는다. Codex는 앱 프로세스의 `CODEX_HOME`을 따르며 파일 인증 저장소만 지원한다. `keyring`·`auto`·`ephemeral`은 덮어쓰지 않고 적용 오류를 표시한다.

## 인증 오류 처리

| 표시 | 처리 |
| --- | --- |
| 구독 액세스 토큰 갱신 필요 | 해당 계정 CLI를 실행한 뒤 사용량 새로고침 |
| 저장된 갱신 토큰 거부 | 계정 카드의 **다시 연결**에서 같은 계정 로그인 |
| 권한 거부 | 계정·프로젝트·조직 접근 정책 확인 |
| API 키 거부 | 열쇠 버튼으로 키 교체 |
| API 조회 권한 부족 | 모델 목록 조회 권한 확인. 생성 권한과는 별개 |
| 요청 제한·네트워크 실패 | 잠시 후 연결 확인 재시도 |
| 설정 적용 실패 | 표시된 설정 형식·권한·인증 저장소 문제 해결 후 **사용** 재시도 |

Claude/Codex 실행 여부만으로 다른 계정의 토큰 갱신을 막지 않는다. 활성 OAuth 계정과 API 해제 때 복원할 정확한 OAuth 스냅샷은 중복 회전하지 않는다.

## 검증 범위

가짜 키·격리된 홈으로 설치된 Claude `auth status --json`과 Codex `login status`가 별도 런처 없이 API 인증을 인식하는 것을 확인했다. 실제 macOS 키체인 왕복·삭제, OAuth 백업·복원, API 간 전환, 쓰기 실패 복구, 외부 설정·새 로그인 보존도 검사했다.

Windows 러너에서도 실제 사용자 DPAPI의 저장·복호화·키 교체·손상 거부·삭제, PowerShell helper의 키 반환, API 해제·구독 전환·활성 연결 삭제 시 OAuth 복원과 설치된 CLI의 API 인증 인식을 확인했다. Windows 경로의 공백·한글·따옴표·`&`·`%변수%`도 포함한다. 코드 푸시 시 [windows-check](../.github/workflows/windows-check.yml)가 자동으로 검사한다.

화면 검사는 실제 배포 프론트에 가짜 Tauri 응답을 연결해 수행했다. 등록창 제목·원래 타이틀바의 네이티브 드래그 호출, 입력 보존, 네 모드의 API 표시, 사용·해제·재시도·교체·삭제를 포함한다. 실제 유료 생성 호출과 Windows GUI의 실제 포인터 조작은 검증하지 않았다. 비용 조회는 로컬 HTTP 서버로 통화 단위·API 키별 필터·페이지 합산·권한 오류·부분 실패·집계 전 상태를 검사했다. 실제 관리자 키로 공급자 비용 조회는 실행하지 않았다. 공식 Anthropic/OpenAI 키를 지원하며 사용자 지정 Base URL, Azure/Bedrock, 토큰별 상세 내역과 공급자의 결제 상한 변경은 지원 범위 밖이다.
