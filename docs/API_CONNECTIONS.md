# API 키 연결 사용법

적용 브랜치: `feat/connection-workspace`. API 키는 구독 계정과 별도로 등록한다. 새 터미널 창을 띄우거나 자동으로 API 과금으로 전환하지 않는다.

## 등록하고 사용하기

1. 상단 보기 버튼을 **관리**로 맞춘다.
2. Claude 또는 Codex 아래 **API 연결 → API 키 등록**을 펼친다.
3. 연결 이름(영문·숫자·하이픈·언더스코어)과 발급받은 키를 입력하고 **키 저장**을 누른다. 이름은 대소문자를 구분하지 않는다. 같은 이름으로 저장하면 키를 교체한다.
4. **연결 확인**을 누른다. 공식 공급자의 모델 목록 API만 조회하며 텍스트 생성은 요청하지 않는다. 성공해도 모델별 생성 권한·잔액·요금 한도까지 확인한 것은 아니다.
5. **실행 명령 복사**를 눌러 작업할 프로젝트의 기존 터미널에 붙여넣는다. macOS는 bash/zsh 터미널, Windows는 PowerShell에서 사용한다. 명령에는 키가 들어 있지 않다.
6. Claude CLI가 처음 API 사용 확인을 물으면 내용을 확인하고 승인한다. API 요청은 구독 요금과 별도로 청구된다.

macOS 명령 형태는 `/bin/bash '/…/.switcher/api-connections/claude/project/run.sh'`, Windows는 `powershell.exe -NoProfile -File '…\run.ps1'`이다. 끝에 CLI 인자를 추가할 수 있다. `claude`/`codex`가 해당 터미널의 PATH에 있어야 한다. Windows 실행 정책이 스크립트를 제한하면 조직 정책을 확인한다. 앱이 실행 정책을 자동 해제하지 않는다.

키 발급·구독과의 차이는 [OpenAI 공식 인증 문서](https://learn.chatgpt.com/docs/auth?surface=cli)와 [Claude 공식 인증 문서](https://code.claude.com/docs/en/authentication), [Claude 키 발급 안내](https://platform.claude.com/docs/en/get-api-key)를 참고한다.

## 기존 로그인과의 관계

API 실행 명령은 자식 CLI에만 키를 전달하며, 연결별 `~/.switcher/api-workspaces/<provider>-<name>/`을 CLI 설정·기록 폴더로 사용한다. 기존 구독 로그인 파일, 셸 설정, 전역 환경변수를 바꾸지 않는다. 따라서 평소 쓰던 `claude`/`codex` 명령은 기존 설정으로 계속 실행된다. API 명령으로 시작한 CLI에는 별도의 초기 설정·신뢰 확인이 나타날 수 있다.

Codex는 공식 OpenAI Responses 엔드포인트와 `env_key`를 사용하는 별도 공급자 설정으로 실행한다. Claude는 `ANTHROPIC_API_KEY`로 실행한다. 상속된 주요 인증·엔드포인트 환경변수는 실행 스크립트에서 제거한다. 관리자가 배포한 정책이나 프로젝트 설정까지 앱이 덮어쓰지는 않으므로 CLI 화면에서 적용된 공급자를 확인한다.

## 저장·교체·삭제

- macOS: `Switcher-API-<provider>-<name>` 키체인 항목. Windows: 현재 Windows 사용자에게 묶인 DPAPI 암호문(`*.dpapi`).
- 메타데이터와 실행 스크립트에는 키 원문이 없다. 키는 입력 후 Rust IPC로 전달되고, 저장 완료/실패 후 입력칸에서 지운다. 목록 조회는 키를 반환하지 않는다.
- **같은 이름으로 다시 등록**하면 키가 교체된다. 새 CLI 실행부터 새 키를 읽으며 이미 실행 중인 CLI는 영향을 받지 않는다.
- **삭제 → 삭제 확인**은 키와 연결 메타데이터·실행 스크립트를 지운다. 별도 CLI 작업 기록은 `api-workspaces`에 남긴다. 공급자 서버의 키까지 폐기하지는 않으므로 완전 폐기가 필요하면 발급 사이트에서도 폐기한다.
- 1차 지원 범위는 공식 Anthropic/OpenAI 키다. 사용자 지정 Base URL, Azure/Bedrock, API 비용·쿼터 표시와 자동 대체 전환은 포함하지 않는다.

## 구독 인증 오류가 날 때

- **사용량 인증 갱신 필요**: 해당 계정 CLI를 실행하고 새로고침한다. 액세스 토큰 만료만으로 구독 로그인이 폐기됐다고 단정하지 않는다.
- **저장된 갱신 토큰 거부**: 카드의 **다시 연결**에서 같은 계정으로 로그인한다. 기존 로그인 임포트가 실제 계정 ID로 프로필을 찾아 갱신한다. 다른 계정으로 로그인하면 그 계정이 별도로 등록되며 기존 프로필을 다른 신원으로 덮어쓰지 않는다.
- **권한 거부**: 계정·조직 정책을 확인한다. 반복 로그인으로 해결된다고 표시하지 않는다.
- **Codex 파일 외 저장소 안내**: 현재 구독 전환 어댑터는 파일 저장소만 지원한다. `CODEX_HOME`은 앱 프로세스에 전달된 값을 따른다. `keyring`/`auto`/`ephemeral` 설정이 감지되면 전환·저장을 막는다. 필요한 경우 사용자가 Codex 공식 문서를 확인해 파일 저장소로 전환하고 다시 로그인해야 한다. 앱은 이를 자동 변경하지 않는다. API 연결은 이 제한과 별개다.

## 검증 범위

가짜 키를 이용한 macOS 키체인 저장/읽기/삭제와 생성된 실행 스크립트의 가짜 CLI 실행은 통과했다. 실 API 키로 모델을 생성하거나 실제 구독 계정을 전환하지 않았다. Windows DPAPI 호출 타입은 Windows 타깃으로 별도 검사했으며, 전체 앱·PowerShell 런처의 Windows 실행 검증은 남아 있다.
