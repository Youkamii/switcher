# API 키 등록과 사용

일반 모드에서 사용할 계정 카드의 **API 키 추가**를 누른다. 계정이 처음이면 Claude 또는 Codex 옆의 **계정 추가**로 로그인해 카드를 만든다. 이 문서는 계정별 키를 지원하는 로컬 빌드 기준이다. 공개 버전 v2.1.2는 **계정·API 추가 → API 키 등록**을 사용한다.

## Codex 계정 전환 범위

위젯은 현재 인증을 먼저 백업하고 선택한 계정의 `auth.json`을 적용한다. **파일 교체만으로 실행 중 인증이 바뀌지는 않으므로 공유 서버 갱신을 이어서 수행한다.** Codex CLI 0.167.0은 인증을 메모리에 유지하며 외부 파일 변경을 자동으로 읽지 않는다. 401 복구 시에도 다른 계정으로의 재읽기를 허용하지 않는다. [해당 버전 AuthManager 구현](https://github.com/openai/codex/blob/rust-v0.167.0/codex-rs/login/src/auth/manager.rs).

구독 계정 전환 뒤에는 **Codex 0.167.0 이상 정식 버전의 관리되는 공유 서버**를 자동 갱신한다. 실행 중인 작업·승인 대기를 기다리고 저장 가능한 대화가 모두 idle일 때 정상 종료를 요청한다. 서버 종료를 확인한 뒤 공식 daemon 명령으로 다시 시작하고, 새 인증이 읽혔는지 확인한다. 기존 Codex TUI의 재연결 기능으로 대화를 이어가는 방식이며 터미널 입력을 주입하지 않는다. Codex 자체 OAuth 갱신을 유지하므로 별도의 외부 토큰 공급자에 의존하지 않는다.

화면의 **선택됨**과 공유 서버 갱신 상태는 별개다. `--no-daemon`, `--profile`, 일반 설정을 덮어쓰는 `-c` 옵션이나 이를 넣는 래퍼, 구형 CLI, Windows 관리자 실행, 독립 stdio 서버처럼 공유 서버를 사용하지 않는 실행은 자동 갱신 대상이 아니다. 이 경우 기존 Codex를 종료한 뒤 같은 터미널에서 `codex resume`으로 이어간다. API 선택은 기존 안내대로 다음 CLI 실행에서 적용한다. 자동 유료 전환은 하지 않는다.

갱신 작업은 별도 headless helper가 수행하므로 위젯을 닫아도 이어진다. Windows에서는 설치 EXE를 잠그지 않는 검증된 복사본을 사용한다. 이미 진행 중인 작업을 강제 종료하지 않으며, 30분간 idle이 되지 않으면 실패 상태로 끝나고 새로고침으로 재시도할 수 있다. 정상 종료 요청 직후 새 작업이 시작된 경합에서는 Codex의 drain이 끝날 때까지 helper가 기다린다. 저장되지 않는 ephemeral 대화는 재시작하지 않는다.

`node scripts/check-codex-session-auth.mjs`는 격리된 홈·가짜 OAuth 계정 두 개로 설치된 Codex를 실행한다. 기존 프로세스는 A, 파일 교체 후 새 프로세스는 B를 읽는지 검사한다. 생성 요청이나 실계정 토큰을 사용하지 않는다. 이 검사는 로그인 인식 범위이며 실제 모델 호출 성공을 뜻하지 않는다.

`cargo test --manifest-path src-tauri/Cargo.toml installed_codex_daemon_reloads_selected_account_without_external_auth -- --ignored --test-threads=1`은 설치된 packaged Codex와 격리 홈·가짜 인증·로컬 HTTP 모델 응답을 쓴다. 작업 중 갱신 대기, 완료 후 B 인증 반영, 같은 thread ID와 대화 내용 복원, managed OAuth 유지까지 확인한다. 실제 OpenAI 모델 호출이나 유료 요청은 하지 않는다. 이 반복 검사는 앱 서버 수준에서 재연결·resume을 수행한다. macOS Codex 0.169.0에서는 별도로 격리 PTY의 실제 TUI와 로컬 HTTPS 응답을 사용해 자동 재연결 후 같은 대화에서 후속 입력이 처리되고 이전 답변이 문맥에 유지되는 것까지 확인했다.

## API 등록

한 계정에 여러 키를 보관할 수 있다. 일반 모드에서는 계정 하단의 **API 키**를 눌러 목록을 접고 펼친다. 다른 세 모드에서는 현재 사용하는 키와 잔액이 소속 계정 아래에 표시된다.

## 등록·전환

1. 일반 모드에서 사용할 **계정 카드 → API 키 추가**를 누르고 창 상단에 표시되는 계정을 확인한다.
2. 키가 없으면 **키 발급 페이지 열기 ↗**를 누른다. Claude 키는 사용할 워크스페이스를 지정해 발급한다. [Claude 공식 안내](https://platform.claude.com/docs/en/get-api-key), [OpenAI 키 관리](https://platform.openai.com/api-keys).
3. 키 이름과 API 키를 입력한다. **저장**은 계정에 키를 추가하고, **저장하고 사용**은 다음 CLI 실행까지 설정한다. 키 이름은 영문·숫자·`-`·`_`로 정하고 다른 계정에서 같은 이름을 쓸 수 있다.
4. **API 사용 중**이 표시되면 설정 적용이 끝난 것이다. 모델 목록 조회 결과는 별도로 표시한다. 조회 성공은 생성 권한·잔액까지 보장하지 않는다.
5. 구독으로 돌아갈 때는 원하는 계정의 **구독 사용** 또는 **전환**을 누른다. API 키 옆의 **해제**는 API 선택 직전 설정을 복원한다.

이미 등록한 연결은 카드의 **사용**만 누르면 된다. 키를 다시 입력하지 않는다. 네 가지 모드 모두 선택된 API를 표시하며, 등록·교체·삭제는 일반 모드에서 한다. API 사용은 구독과 별도 과금된다. 실행 중인 CLI의 인증 메모리는 바꾸지 않으므로 다음 CLI 실행부터 적용된다. 새 터미널 창은 만들지 않는다.

등록·키 교체·완료 화면이 열린 상태에서도 **창 상단이나 대화상자 제목을 잡아 이동**할 수 있다. 이동 중 입력값은 유지한다.

## 기존 키와 계정 관리

이전 버전의 키는 해당 공급자 아래 **기존 키 연결**에 나타난다. 각 키의 소속 계정을 선택하고 **연결**을 누르면 그 계정의 키 목록에 들어간다. 연결 시 원래 키, 확인 상태, Console 잔액 기록과 현재 CLI 선택을 보존한다.

계정 이름을 바꿔도 키는 같은 계정에 속한다. 계정을 삭제하면 하위 키는 **기존 키 연결**에서 다시 연결할 수 있다. 원래 계정을 다시 추가하면 그 계정의 키가 다시 표시된다.

## 키 목록

| 버튼 | 동작 |
| --- | --- |
| 사용 / 해제 | 저장된 API 적용 / 이전 설정 복원 |
| 순환 화살표 | 모델 목록으로 연결 확인, Claude 선불 잔액 새로고침 |
| 결제 화면 ↗ | 해당 공급자의 공식 결제 페이지 열기 |
| 열쇠 | 새 키로 교체. 사용 중인 키라면 **저장하고 사용**으로 적용 |
| 휴지통 | 3초 안에 한 번 더 눌러 삭제. 사용 중이면 설정 복원 후 삭제 |

같은 이름의 새 등록은 기존 키를 덮어쓰지 않는다. 교체에는 열쇠 버튼을 사용한다. 키 저장에는 성공했지만 설정 적용이 실패하면 **키 저장 완료**와 오류, **사용** 재시도 버튼을 표시한다. 저장한 키로 재시도하므로 재입력할 필요가 없다.

확인 결과·시각은 메타데이터에 보관하며, 키 교체 시 초기화한다. 확인 중 교체·삭제가 일어나면 낡은 응답을 반영하지 않는다. 입력값은 저장 성공·실패·취소 때 지우고 다시 표시하지 않는다.

## API 크레딧 잔액

일반 모드는 각 API 카드에, 컴팩트·미니멀·엣지는 선택한 API에 잔액을 표시한다. 개인 계정도 그대로 사용할 수 있다. Console의 ‘조직’은 키를 발급한 결제 계정이고, 그 안에서 발급한 여러 키가 한 잔액을 공유한다. 카드에 나타나는 조직 이름은 등록한 키로 Anthropic에 직접 확인한다. [Claude 조직 정보 API](https://platform.claude.com/docs/en/manage-claude/admin-api)

| 카드 표시 | 출처와 사용법 |
| --- | --- |
| **조직 선불 잔액**과 금액 | 키와 같은 Console 조직에 속한 유효한 OAuth 로그인이 있으면 공급자가 반환한 선불 금액을 표시한다. 확인 시각은 금액에 포인터를 올려 볼 수 있다. 새로고침하면 다시 조회한다. |
| **조직 크레딧**과 **Console 확인 · 날짜/시각** | 그 시각에 사용자가 Console 대시보드에서 가져온 금액이다. 이 확인값에는 대시보드가 표시한 월간 지급분과 구매 크레딧이 반영될 수 있다. 대시보드를 다시 가져오면 갱신된다. |
| **키를 발급한 Claude Console에서 확인** | 현재 로그인으로 API 지갑을 자동 조회할 수 없다. 개인 구독과 API 결제는 같은 이메일이라도 조직이 다를 수 있다. 카드의 **대시보드 가져오기**를 사용한다. |
| **다시 연결 / 권한 없음 / 조회 실패** | 자동 조회 상태를 확인하고 다시 연결하거나 새로고침한다. 확인값이 있으면 출처와 시각을 함께 보여준다. 공급자가 0을 반환했거나 대시보드에 0이 표시된 경우에만 0을 표시한다. |
| **OpenAI · 결제 화면에서 확인** | 해당 조직의 OpenAI Billing을 연다. 일반 API 키로 선불 잔액을 읽는 공개 경로는 확인되지 않았다. [OpenAI 선불 결제 안내](https://help.openai.com/en/articles/8264644-setting-up-and-managing-prepaid-api-billing) |

### Claude 대시보드 금액 가져오기

1. 일반 모드에서 해당 API 카드의 **대시보드 가져오기 → 대시보드 열기 ↗**를 누른다. 로그인한 개인 Console 이름이 위젯에 표시된 이름과 같은지 확인한다. [Claude Console 대시보드](https://platform.claude.com/dashboard)
2. 조직 이름과 **조직 크레딧**이 함께 있는 대시보드 내용을 복사해 위젯에 붙여넣는다. 앱이 `조직 크레딧` 또는 `Organization credits` 바로 아래의 USD 금액을 찾는다. 이번 달 지출·티어 한도는 가져오지 않는다.
3. 네 가지 모드에서 **Console 확인** 시각을 확인한다. 복사한 원문·키 목록·이메일은 저장하지 않는다. 확인값은 해당 연결과 확인된 조직 ID에 묶어 이 컴퓨터에 저장한다. 키 교체 후에는 새 키에 맞는 값을 다시 확인한다.

자동 조회는 현재 선택한 공식 Anthropic `user_oauth` 프로필 또는 Switcher에 보관한 같은 조직의 Console 로그인을 사용한다. 실행 키와 로그인 각각의 조직을 공급자에게 확인한 후에만 선불 크레딧을 요청한다. Claude Code가 구독 추가 사용량에도 쓰는 이 경로는 공개 결제 API로 문서화되어 있지 않아 권한이나 공급자 변경에 따라 응답하지 않을 수 있다. 구독 지갑의 금액을 API 크레딧으로 가져오지 않는다. 공식 Console 프로필의 토큰 갱신은 원래 CLI가 관리한다. 읽은 금액과 로그인·권한 상태는 최대 5분간 메모리에 보관하며 일시적 실패는 30초 뒤 재시도한다. 키나 로그인 변경도 확인한다. [Claude Console 인증](https://code.claude.com/docs/en/authentication) · [Anthropic CLI 프로필](https://platform.claude.com/docs/en/cli-sdks-libraries/cli/authentication)

구독에 포함된 월간 API 크레딧의 전체 내역과 만료일은 Console 결제 화면에서 확인한다. 기존 연결의 월 예산·수동 사용 금액·관리자 조회 키는 사용하지 않는다. 연결을 삭제하면 이전 데이터와 로컬 조회 키도 정리한다. [Claude API 결제 안내](https://support.claude.com/en/articles/8977456-how-do-i-pay-for-my-claude-api-usage) · [월간 API 크레딧 안내](https://support.claude.com/en/articles/17154008-monthly-api-credits-for-max-ultra-and-team-plans)

## 적용 방식과 복원

- 저장된 키는 macOS Keychain / Windows 현재 사용자 DPAPI로 보호한다. 목록·로그·보조 스크립트에 키 원문을 넣지 않는다.
- Claude는 사용자 `settings.json`의 공식 `apiKeyHelper`가 보안 저장소에서 키를 읽는다. 구독 OAuth 자격증명은 보존한다. 충돌하는 사용자 설정의 API 인증·클라우드 환경 항목은 적용 전에 백업하고, 공식 Anthropic 엔드포인트를 선택한다. [Claude 인증 우선순위](https://code.claude.com/docs/en/authentication), [apiKeyHelper](https://code.claude.com/docs/en/settings-reference#apikeyhelper).
- Codex는 사용자 `config.toml`에 공식 OpenAI API 공급자를 선택하고 표준 `auth.json`에 활성 API 키를 쓴다. **Codex가 읽는 활성 인증 파일에는 키가 들어간다.** Unix에서는 0600 권한으로 쓰며, 저장 연결의 정본은 OS 보안 저장소에 둔다. 기존 인증은 전환 전에 백업한다. [Codex 인증 저장소](https://learn.chatgpt.com/docs/auth).
- 복원 기록은 `~/.switcher/api-active/<provider>/`에 저장한다. 앱이 적용한 값과 현재 값이 같은 항목만 되돌리고, 사용자가 그 사이 바꾼 다른 설정·새 OAuth 로그인은 보존한다. Codex TOML의 다른 설정과 주석도 유지한다.
- API를 명시적으로 선택하면 자동 계정 전환(TFSD)을 해제한다. 구독 오류·사용량 초과 때문에 API로 자동 전환하지 않는다.
- 삭제는 로컬 키·연결 정보·보조 스크립트를 지운다. 공급자 서버의 키 폐기는 발급 페이지에서 별도로 한다.

사용자·프로젝트·조직 정책의 우선순위는 CLI가 결정한다. 별도 구성 경로, 프로젝트 인증 덮어쓰기, 관리 정책으로 제한된 환경은 기본 사용자 설정 적용만으로 보장하지 않는다. Codex는 앱 프로세스의 `CODEX_HOME`을 따르며 파일 인증 저장소만 지원한다. `keyring`·`auto`·`ephemeral`은 덮어쓰지 않고 적용 오류를 표시한다.

## 인증 오류 처리

| 표시 | 처리 |
| --- | --- |
| 구독 액세스 토큰 갱신 필요 | 해당 계정 CLI를 실행한 뒤 사용량 새로고침 |
| 저장된 갱신 토큰 거부 | 계정 카드의 **다시 연결**에서 같은 계정 로그인 |
| 권한 거부 | 계정·프로젝트·조직 접근 정책 확인 |
| API 키 거부 | 열쇠 버튼으로 키 교체 |
| API 조회 권한 부족 | 모델 목록 조회 권한 확인. 생성 권한과는 별개 |
| 요청 제한·네트워크 실패 | 잠시 후 연결 확인 재시도 |
| 설정 적용 실패 | 표시된 설정 형식·권한·인증 저장소 문제 해결 후 **사용** 재시도 |

Claude/Codex 실행 여부만으로 다른 계정의 토큰 갱신을 막지 않는다. 활성 OAuth 계정과 API 해제 때 복원할 정확한 OAuth 스냅샷은 중복 회전하지 않는다.

## 검증 범위

가짜 키·격리된 홈으로 설치된 Claude `auth status --json`과 Codex `login status`가 별도 런처 없이 API 인증을 인식하는 것을 확인했다. 실제 macOS 키체인 왕복·삭제, OAuth 백업·복원, API 간 전환, 쓰기 실패 복구, 외부 설정·새 로그인 보존도 검사했다.

Windows 러너에서도 실제 사용자 DPAPI의 저장·복호화·키 교체·손상 거부·삭제, PowerShell helper의 키 반환, API 해제·구독 전환·활성 연결 삭제 시 OAuth 복원과 설치된 CLI의 API 인증 인식을 확인했다. Windows 경로의 공백·한글·따옴표·`&`·`%변수%`도 포함한다. 코드 푸시 시 [windows-check](../.github/workflows/windows-check.yml)가 자동으로 검사한다.

화면 검사는 빌드된 프론트에 가짜 Tauri 응답을 연결해 네 모드의 금액·확인 시각, 등록창 드래그·입력 보존, 키 교체·재시도·대시보드 가져오기를 검사한다. 격리된 홈과 로컬 HTTP 서버로 실제 0·통화 단위, 권한 거부, 조직 일치, 키 교체·응답 경합, 확인값 저장·복원도 검사한다. macOS의 실제 API 연결에서는 키 발급 조직과 사용자가 제공한 Console 화면을 대조하고, 해당 화면의 금액을 저장한 뒤 새 조회에서 같은 값과 시각이 복원되는 것까지 확인했다. 해당 연결의 구독 OAuth에는 Console 자동 조회 권한이 없었다. 실계정 정보와 금액은 이 저장소에 포함하지 않는다.
