# switcher 코드 리뷰 테스트 결과

검증일: 2026-11-10 · 제품 기준: v2.0.2, `ef96b50`

**기존 테스트와 macOS 앱 빌드는 통과했지만, 실제 CSS 배치 검사에서 빈자리와 카드 이동 결함을 재현했다.** 제품 수정 전 기준선이며, 개선 완료 결과가 아니다. 구현 범위와 완료 기준은 [개선 계획](IMPROVEMENT_PLAN.md)에 정리했다.

## 실행 환경

| 항목 | 값 |
| --- | --- |
| OS | macOS 27.0.1, arm64 |
| Node | v24.3.0 |
| Rust | rustc 1.96.0 |
| 브라우저 | Google Chrome 156.0.8078.76, headless |
| UI 픽스처 | 저장소의 index.html, theme.css, styles.css + 가짜 계정 DOM |

레이아웃 검사는 임시 브라우저 프로필과 로컬 파일을 사용한다. 앱의 main.ts·Tauri IPC는 실행하지 않으며, 실제 계정 파일을 읽거나 네트워크 인증을 수행하지 않는다. 테스트 종료 후 임시 디렉토리를 제거한다.

## 실행 결과

| 검사 | 결과 | 해석 |
| --- | --- | --- |
| `npm test` | 93 통과, 0 실패 | 기존 프론트·릴리스 검사 통과 |
| `cargo test` | 215 통과, 0 실패, 15 ignored | 현재 macOS에서 컴파일된 Rust 테스트 통과. Windows 전용 구현 검증을 뜻하지 않음 |
| `npm run tauri build -- --bundles app` | 성공 | TypeScript/Vite 빌드, Rust release 빌드, switcher.app 생성 |
| `node scripts/review-layout.mjs` | 4 통과, 4 실패, 종료 코드 1 | 서로 다른 두 UI 결함을 총 네 시나리오에서 재현 |

앱 산출물: `src-tauri/target/release/bundle/macos/switcher.app`.

Rust 빌드에는 기존 unused variable/dead code 경고 4건이 있었다. 앱은 ad-hoc 서명으로 생성됐으며 notarization은 수행되지 않았다. 빌드 성공은 설치·실행·전체화면 Space 동작의 검증을 대신하지 않는다. 이 검토에서는 생성된 앱을 실행하거나 배포하지 않았다.

## 실제 레이아웃 측정

| 케이스 | 기대 | 실측 | 판정 |
| --- | --- | --- | --- |
| Claude·Codex 모두 숨김 | 숨긴 각 행 높이 0px | 각 19px, `display:flex` | 실패 |
| Claude 표시·Codex 숨김 | Codex 행 높이 0px | 19px | 실패 |
| Claude 숨김·Codex 표시 | Claude 행 높이 0px | 19px | 실패 |
| Claude·Codex 모두 표시 | 숨김 위반 없음 | 모두 표시 | 통과 |
| 일반 카드에 `.hit-hover` 적용 | 다음 카드 이동 1px 이하 | y=184→216, 32px 이동 | 실패 |
| 일반 360px 버튼 가로 경계 | 보이는 버튼이 shell 안에 있음 | 경계 안 | 통과 |
| 컴팩트 240px 버튼 가로 경계 | 동일 | 경계 안 | 통과 |
| 미니멀 120px 버튼 가로 경계 | 동일 | 경계 안 | 통과 |

숨김은 실제 `hidden` 속성과 computed style·DOM geometry를 측정했다. 호버는 macOS 네이티브 폴러가 붙이는 동일한 클래스를 적용했다. 시스템 행은 켜둔 상태이고 도구 검사에서는 클램셸 버튼도 표시했다. 버튼 경계 검사는 현재 정적 한국어 라벨과 기본 상태에서의 가로 배치만 검증한다. 클릭 가능 여부, 창 밖 팝업, 긴 번역, 모든 상태 전환까지 통과한 것은 아니다.

**수정 대상은 버튼의 가로 넘침으로 확정하지 않았다.** 이번에 확인한 이동은 호버로 카드 버튼 행이 펼쳐지면서 다음 카드가 밀리는 현상이다. 사용자 환경의 다른 버튼 이동은 네이티브 후속 검증에 포함한다.

## 재실행 방법

저장소 루트에서 실행한다. Chrome/Chromium이 없으면 `CHROME_BIN`에 실행 파일 경로를 지정한다. 스크립트가 브라우저를 설치하지 않는다.

```sh
npm test
npm run tauri build -- --bundles app
node scripts/review-layout.mjs --output /tmp/switcher-layout-result.json
```

Rust 검사는 `src-tauri`에서 실행한다.

```sh
cargo test
```

레이아웃 검사 종료 코드는 0=모든 기준 통과, 1=제품 배치 기준 위반, 2=브라우저 부재 등 검사 실행 오류다. 현재 기준선의 종료 코드 1을 테스트 도구 오류나 전체 테스트 성공으로 해석하지 않는다. 기존 `npm test`에 자동 편입하지 않은 별도 감사 검사이며, 결함 수정 후 회귀 검사로 정식 편입할 수 있다.

[측정 JSON](review-layout-baseline.json)은 이번 제품 기준의 고정 기록이다. 향후 결과를 비교하려면 다른 경로에 출력하고, 현재 기준선 파일을 묵시적으로 덮어쓰지 않는다.

## 인증에 대해 확인한 것과 남은 것

기존 Rust 테스트에는 활성 프로필 갱신 제외, 갱신 응답 병합, pending 복구, 호출 취소 뒤 응답 저장, 갱신 중 이름 변경 대기, 캐시·백오프 관련 검사가 포함돼 있으며 이번 실행에서 통과했다. 이것은 가짜 데이터와 로컬 테스트의 결과다.

| 항목 | 현재 증거 | 다음 검증 |
| --- | --- | --- |
| 활성 프로필 갱신 제외 | 코드 및 단위 테스트 | CLI 미실행 상태의 실제 만료 표시와 복구 |
| 과도한 만료 분류 | `post_refresh_and_land` 코드 분기 | 로컬 HTTP 서버로 invalid_grant·403·404·429·5xx 각각 주입 |
| stale가 인증 오류를 숨김 | 응답 모델·폴백 경로 확인 | 캐시 유무별 UI와 재연결 버튼 검사 |
| 외부 CLI와 갱신 경합 | 설계상 가능성 | 격리된 가짜 CLI/저장소로 A 실행→B 전환→A 갱신 순서 재현 |
| 실제 반복 재로그인 원인 | 미확정 | 사용자 증상 위치와 비밀을 제거한 상태·오류 코드 수집 |
| API 키 연결 | 미구현 | 구현 후 가짜 키와 저장소 어댑터 검증, 실키 검증은 별도 |

`cargo test -- --ignored real_ --test-threads=1`은 실행하지 않았다. 실계정 인증·토큰 회전·시스템 상태를 건드릴 수 있는 검사는 가짜 데이터 검사와 분리했다. 실제 API 유료 요청도 실행하지 않았다.

## 구현 후 수용 검사

- [ ] 숨김 조합 검사 4개와 카드 이동 검사 모두 통과.
- [ ] 손잡이 크기와 히트 영역이 실제 표시 항목에 맞고 빈 구분선이 남지 않음.
- [ ] 연결 0/1/다수, 긴 표시 이름, 6개 언어에서 버튼·팝업 잘림 없음.
- [ ] 재조회·실패·재연결·호버 동안 헤더 위치와 키보드 포커스 유지.
- [ ] macOS 비활성 패널, 전체화면 Space, 절전 복귀에서 갱신·메뉴·취소 정상.
- [ ] Windows 실제 앱에서 표시 배율과 클릭 통과, 로그인 취소·프로세스 종료 확인.
- [ ] 오류 종류에 맞는 복구 동작 제공. 403을 무조건 로그인 만료로 표시하지 않음.
- [ ] API 키 등록·교체·삭제·OAuth 왕복 전환과 저장소 잠김 시 복구 확인.
- [ ] 업데이트 자산의 잘못된 서명·잘린 파일을 실행 전에 거부.

API·인증·레이아웃 개선이 구현되기 전에는 이 체크리스트를 완료로 표시하지 않는다.
