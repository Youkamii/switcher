# switcher 개선 계획

작성일: 2026-11-10 · 검토 기준: v2.0.2, `ef96b50`

현재 우선 과제는 **버튼과 화면이 움직이지 않는 UI, 미사용 AI의 빈자리 제거, 인증 문제의 정확한 안내, API 키 연결**이다. 작은 위젯에 관리 기능과 도구를 계속 추가하는 방식에서 벗어나, 관리 화면과 상시 위젯의 역할을 분리한다. Tauri 2, Rust, 바닐라 TypeScript, Vite, npm은 유지한다.

이 문서는 최초 리뷰의 개선 목표와 후속 계획이다. UI·인증 오류 처리·API 연결은 코드에 적용했다. **최종 구현·검증 결과는 [적용 현황](IMPLEMENTATION_STATUS.md)이 정본**이며, 아래 장기 제안이 모두 구현됐다는 뜻은 아니다. [최초 테스트 결과](REVIEW_TEST_RESULTS.md)는 수정 전 기준선이다.

## UI의 목표 구조

### 관리 화면과 위젯

**관리 화면**은 연결 추가, API 키 등록, 재연결, 이름 변경, 삭제, 표시 설정을 담당한다. 계정별 조작은 언제나 같은 위치에 둔다. **위젯**은 선택한 연결의 상태와 사용량, 명시적인 전환만 제공한다. 일반 420px·컴팩트 280px·미니멀 120px·엣지 80px의 네 모드를 모두 유지한다. 관리 기능은 기존 일반 모드에 배치하며, 상단에서 네 모드를 직접 선택한다.

관리 화면의 구성 예시:

```text
switcher                                     [설정]
연결                           [+ 연결 추가]

Claude · 개인                 구독 · 사용 중
5시간 68% 사용 / 주간 24% 사용
연결 정상 · 1분 전 확인                   [⋯]

Codex · 업무                  구독     [전환]
재연결 필요                       [다시 연결]

OpenAI · 개발 프로젝트        API      [전환]
연결 확인됨 · API 별도 과금               [⋯]

위젯에 표시할 연결과 도구 선택
```

위젯의 구성 예시:

```text
switcher                          [↻] [⋯]
Claude · 개인                      사용 중
5시간  ━━━━━━━──── 68%      2시간 후 초기화
주간   ━━━──────── 24%      4일 후 초기화

Codex · 업무                       [전환]
연결 정상 · 1분 전 확인
```

초기 디자인 기준은 본문 13px, 보조 정보 12px, 주요 버튼 높이 32px, 아이콘 버튼 28~32px, 간격 4/8/12/16px로 둔다. 관리 화면은 420px 안팎, 위젯은 280px 안팎을 시안 기준으로 삼고 화면 배율과 긴 번역 문자열로 검증한다. 이는 확정된 제품 치수가 아닌 검증할 초안이다.

이모지 대신 동일한 선 굵기의 SVG 아이콘을 쓰고 주요 작업에만 강조색을 쓴다. 사용량 막대와 오류 상태는 색 외에 숫자·텍스트를 함께 제공한다. 기본은 읽기 쉬운 패널로 하고, 투명도와 액체 효과는 선택 기능으로 둔다. `prefers-reduced-motion`에서는 장식 애니메이션을 중지한다.

### 빈자리와 미사용 상태 규칙

| 상태 | 위젯 | 관리 화면 |
| --- | --- | --- |
| 표시 설정 꺼짐 | 행·제목·구분선·간격 모두 제거 | 설정에서 다시 켤 수 있음 |
| 연결된 계정 없음 | 해당 공급자 영역을 생성하지 않음 | 공통 ‘연결 추가’ 제공 |
| 계정은 있으나 지금 CLI를 쓰지 않음 | 기본적으로 계속 표시 | 표시 설정 제공 |
| 사용자가 ‘사용하지 않는 연결 숨기기’를 선택함 | 합의한 활동 기준으로 숨김 | 숨겨진 연결도 찾을 수 있음 |
| 인증 실패 | 빈칸 대신 상태와 재연결 동작 | 오류 종류와 복구 안내 |
| 일시적인 조회 실패 | 마지막 수치·확인 시각·재시도 상태 | 진단 정보 |
| 모든 AI가 숨겨짐 | 선택한 시스템 도구만 표시. 도구도 없으면 작은 연결 추가 상태 | 모든 연결을 관리할 수 있음 |

사용량 0%는 ‘미사용’ 판정 기준으로 쓰지 않는다. 현재 프로세스 탐지만으로 세션의 실제 계정을 확정하지 않는다. 숨김 기능 때문에 사용자가 추적하던 계정이 예고 없이 사라지지 않도록 한다.

### UI 구현 작업

1. `.edge-gauge-row[hidden] { display: none; }`처럼 해당 컴포넌트의 숨김을 보장한다. 전역 `[hidden]` 재정의는 다른 모달·버튼에 미칠 영향을 확인한 뒤 결정한다.
2. 고정 116px 손잡이·86px 게이지 높이를 표시 행과 패딩에서 계산한다. SYSTEM 앞 구분선도 앞에 AI 행이 있을 때만 둔다. 네이티브 히트 영역도 함께 갱신한다.
3. 카드 안에 일정한 액션 슬롯을 두고 전환 버튼을 상시 제공한다. 다시 연결·이름 변경·삭제는 카드 우측에 같은 크기의 SVG 아이콘으로 모두 표시한다. 전환/사용 중 슬롯 바로 아래에 고정해 활성·비활성 계정의 위치가 일치한다.
4. 호버는 색·테두리만 바꾸게 하고 `hoverActions`의 창 높이 재계산과 삭제 유예에 의존하는 UX를 제거한다. 삭제는 별도 확인 단계로 제공한다.
5. 헤더는 고정된 액션 열을 가진 grid로 구성한다. 좁은 모드에서 버튼을 임의 줄바꿈하지 않고 부가 동작을 메뉴로 보낸다.
6. 목록 상태를 DOM과 분리하고 계정 ID별로 필요한 부분만 갱신한다. 전체 `replaceChildren`에 의존하는 포커스 복원과 비동기 렌더 경합을 줄인다.
7. 창 크기는 모드·표시 항목·사용자 설정이 바뀔 때 조절한다. 조회 성공·오류·호버마다 창 전체가 움직이지 않게 상태 영역을 설계한다.

완료 기준: 숨긴 행 높이 0px, 호버 전후 다음 카드 좌표 차이 1px 이하, 헤더 버튼 좌표 고정, 연결 0/1/다수에서 불필요한 빈칸 없음. 키보드 Tab/Enter/Escape, 메뉴 닫힘 후 포커스 복귀, macOS 비활성 패널에서도 같은 동작을 확인한다.

## 인증과 사용량 개선

### 상태 모델을 분리한다

현재 `Usage`의 stale 여부만으로 로그인 상태까지 표현하지 않는다. 공급자 응답 원문 대신 구조화한 오류 코드를 IPC로 전달한다.

```ts
type AuthState =
  | 'ready'
  | 'refresh_due'
  | 'refreshing'
  | 'reauth_required'
  | 'permission_denied'
  | 'unsupported_store'
  | 'unknown';

type UsageState = 'fresh' | 'stale' | 'unavailable' | 'unsupported';
// 응답에는 authState, usageState, checkedAt, retryAt,
// errorCode와 허용된 복구 동작을 포함한다. 토큰 원문은 포함하지 않는다.
```

`reauth_required`는 공급자가 문서화한 갱신 자격증명 폐기 오류를 확인했을 때 사용한다. 단순 액세스 토큰 만료는 `refresh_due`다. 네트워크 장애·429·5xx는 인증 폐기와 분리한다. 403은 권한·정책 거부일 수 있으므로 바로 만료라고 단정하지 않는다. 알 수 없는 4xx와 리다이렉트도 별도 오류로 남긴다.

### 갱신 순서

1. 실제 CLI 저장 위치와 인증 방식을 확인한다. 지원하지 않는 저장소는 명시적으로 표시한다.
2. 최신 활성 저장소와 프로필을 읽고, 갱신 응답 복구 파일이 있으면 먼저 복구한다.
3. 갱신 소유권이 확인된 계정만 계정별 단일 작업으로 갱신한다. 내부 잠금을 CLI와 공유하는 잠금으로 오해하지 않는다.
4. 새 갱신 응답은 기존 pending 저장·복구 흐름을 유지한다. 파일 쓰기 실패나 호출 취소 때 새 토큰을 잃지 않게 한다.
5. 성공 후 인증 상태와 사용량을 따로 갱신한다. 실패 시 캐시 수치를 보여주더라도 오류 이유와 필요한 동작은 남긴다.

갱신 시점을 Rust 서비스에서 관리하고 UI는 이벤트를 구독한다. 절전 복귀·네트워크 복구 때 재평가하되 요청을 한꺼번에 보내지 않는다. **활성 계정 보호를 단순 제거하거나 전체 갱신 주기를 줄이는 것으로 해결하지 않는다.**

장기적으로 계정별 `CLAUDE_CONFIG_DIR`/`CODEX_HOME`을 사용하는 실행 경로를 검토한다. 별도 환경에서 CLI가 자기 인증을 관리하게 할 수 있지만, 설정·세션 기록·IDE 연결에 미치는 영향이 있다. 기존 CLI를 모두 이 방식으로 강제 전환하지 않고 선택 기능으로 검증한다. 새 터미널 창을 자동으로 띄우지 않는다.

### 재연결과 진단

재연결은 해당 카드에서 시작하고 기존 프로필 ID·이름·표시 설정을 유지한다. 사용자가 다른 계정으로 로그인하면 묵시적으로 덮어쓰지 않고 다른 연결임을 알린다. 취소·실패 시 기존 자격증명을 보존한다.

진단에는 로컬 프로필 ID, 공급자, 인증 방식, 저장소 종류, CLI 버전, 오류 분류, 마지막 성공 시각만 기록한다. Authorization 헤더, 키·토큰·일회용 코드, 공급자 응답 원문은 제외한다. 진단 내보내기는 사용자가 확인할 수 있는 미리보기를 제공한다.

완료 기준: 액세스 토큰 만료와 재로그인 필요를 구분하고, stale 수치 옆에도 인증 상태가 남는다. 갱신 실패·429·파일 저장 실패·재연결 취소·동시 갱신을 가짜 데이터와 로컬 서버로 테스트한다. 기존 ‘활성 백업 → 대상 복사’ 순서는 유지한다.

## API 키 연결 설계

### 사용자 흐름과 범위

`연결 추가 → Claude 또는 Codex → 구독 로그인 또는 API 키 → 표시 이름·키 입력 → 저장 → 적용`으로 구성한다. 1차 범위는 공식 Anthropic/OpenAI 연결이다. 커스텀 Base URL, 프록시, Azure·Bedrock 등은 별도 후속 범위로 둔다.

API 키는 구독 OAuth의 갱신 토큰이 아니다. API 프로필에 OAuth 갱신 로직이나 구독 사용량 엔드포인트를 적용하지 않는다. 구독에서 API로 자동 전환해 과금을 시작하는 기능은 기본 비활성으로 둔다. API도 폐기·만료·권한 제한이 있을 수 있다.

### 데이터와 비밀 저장

- 프로필의 영속 ID는 이름이나 이메일과 분리한다. OAuth 계정은 공급자 신원으로, API 프로필은 로컬 ID로 관리한다. 키 해시를 외부 식별자로 노출하지 않는다.
- 메타데이터는 `schemaVersion`, `id`, `provider`, `authKind`, `displayName`, `secretRef`, 표시 설정을 갖는다. OAuth 신원 필드는 해당 방식에만 적용한다.
- API 키는 macOS Keychain, Windows Credential Manager/DPAPI 등 OS 보호 저장소에 두고 메타데이터에는 참조만 둔다. 추가 Rust 의존성은 구현 시 범위를 확인한다.
- 입력한 키를 저장하기 위해 IPC로 전달하는 것은 허용하되, 목록·조회 응답에는 키 원문을 반환하지 않는다. localStorage·설정 JSON·로그·프로세스 인자에 보관하지 않는다.
- 기존 OAuth 프로필은 1차에 저장 형식을 강제 변경하지 않는다. 새 메타데이터를 병행하고 백업·복구 경로를 보존한다. 구버전은 API 프로필을 오인하지 않게 별도 저장 경로 또는 명확한 스키마 경계를 사용한다.

### 공급자별 적용

| 대상 | 구현 방향 | 주의할 점 |
| --- | --- | --- |
| Codex | 별도 `CODEX_HOME`에서 공식 OpenAI 공급자와 `env_key` 설정으로 실행 | 기존 OAuth `auth.json`과 분리. 설치된 CLI로 런처 인자·버전 실행을 검증. |
| Claude Code | `apiKeyHelper`가 OS 저장소의 선택된 API 키를 CLI에 전달하는 경로 검토 | 기존 helper·환경변수·조직 정책의 우선순위를 감지. 사용자 설정 전체를 덮어쓰지 않음 |
| 기존 터미널 | 설정 또는 지원되는 helper를 통해 다음 실행에 적용 | GUI 프로세스의 환경변수 변경은 이미 실행 중인 터미널의 환경을 바꾸지 못함. 기존 세션에 즉시 반영된다고 표시하지 않음 |

단순한 키 저장 성공을 ‘API 연결 확인’으로 표시하지 않는다. 인증 확인이 가능한 최소 요청을 별도 동작으로 제공하고, 모델 생성 요청이 필요하면 비용 발생 가능성을 명시한 뒤 실행한다. 검증 전·검증 성공·권한 부족을 구분한다.

API 카드에는 ‘API · 별도 과금’, 연결 검증 시각, 선택 상태를 표시한다. 일반 API 키로 계정 전체의 비용을 조회할 수 있다고 가정하지 않는다. 비용을 확인할 수 없으면 공급자 대시보드 링크를 제공하고, 추정치를 표시할 경우 관측 범위와 추정임을 명시한다. 구독의 5시간·주간 막대를 API 키에 재사용하지 않는다.

완료 기준: 키 등록·교체·삭제, 독립 API 실행과 기존 OAuth 보존, 재시작 복원, 저장소 잠김, 잘못된 키, 설정 충돌을 검증한다. API 프로필은 TFSD 구독 자동 전환 후보에서 기본 제외한다. 키를 포함한 파일이나 로그가 생성되지 않는지 검사한다.

## 구조와 보안 보강

`src/main.ts`에서 계정 상태, 카드 렌더, 로그인 패널, 창 배치, 도구를 분리한다. Rust는 Tauri 커맨드를 얇게 두고 자격증명 저장소·인증 방식·공급자별 사용량·갱신 조정을 나눈다. 새 프레임워크 도입 없이 단계적으로 추출한다. 기존 잠금의 순서와 백업 불변식부터 테스트로 고정한다.

자동 업데이트는 앱에 내장된 신뢰 공개키로 서명된 자산을 검증한 뒤 압축 해제·교체한다. 같은 위치에서 받은 해시만 비교하는 것을 배포자 인증으로 취급하지 않는다. 앱 업데이터와 npm 설치 경로에 동일한 검증 정책을 적용한다. 잘못된 서명·잘린 파일·다른 플랫폼 자산은 실행 전에 거부하고 기존 앱은 유지한다. macOS ad-hoc 서명은 이 배포자 검증을 대체하지 않는다.

| 3. 인증 안정화 | 상태 모델, 오류 분류, 카드 재연결, 저장소 진단 | 오래된 사용량이 오류를 숨기지 않음. 가짜 서버 장애·취소·갱신 경합 테스트 통과 |

각 단계에서 변경하지 않는 데이터의 이전/이후 해시 등으로 보존 여부를 로컬 확인하되, 토큰 파일 내용·해시를 공개 보고서에 싣지 않는다. API 키 등록이나 실제 로그인은 이 문서 작성 과정에서 수행하지 않았다.
